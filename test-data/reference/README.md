# Reference Data

Expected output values for integration tests. Generated by running
`recast-rs` with the config parameters listed in each JSON file.

## How values were generated

Each mesh was loaded with `TriMesh::from_obj()`, built with
`RecastBuilder::build_mesh()` using the config in the JSON file, and the
output counts were recorded. Spatial query results were generated with
`NavMeshQuery::find_nearest_poly()`.

## Config note

The test config uses voxel-unit values for walkable parameters
(`walkable_height=2`, `walkable_radius=1`, `walkable_climb=1`). DotRecast
tests use world-unit agent parameters (`agentHeight=2.0`, `agentRadius=0.6`,
`agentMaxClimb=0.9`) which convert to larger voxel values
(`walkable_height=10`, `walkable_radius=2`, `walkable_climb=4`). This
produces fewer polygons in DotRecast output. Direct count comparison between
recast-rs and DotRecast requires matching the converted voxel values.

## Pathfinding

Multi-polygon pathfinding (`find_path` returning >1 polygon) is not tested
because polygon link setup in `build_from_recast` has a known issue that
limits paths to single polygons. Spatial queries (`find_nearest_poly`) work
correctly and are tested.
